# Security reporting

Do not post exploit details, credentials, exported workout data, or other private information in a public issue.

Check the repository's GitHub **Security** tab for a private vulnerability-reporting option. Availability depends on the repository settings. If no private reporting option is available, open a public issue with only a brief, non-sensitive request for a private contact route; do not include reproduction details until a private route is established.

When reporting privately, include the affected version or commit, browser and operating system when relevant, impact, and minimal reproduction steps using synthetic data. Do not send real workout backups or secrets.

This repository does not publish a response-time commitment or a supported-version policy.
