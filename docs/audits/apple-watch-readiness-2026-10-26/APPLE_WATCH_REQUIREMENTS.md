# Apple Watch Ultra 2 requirements and implementation matrix

Audit date: 26 October 2026. Scope: Forma routine selection, explicit start, Watch workout collection, both-device control, reliable finish and synchronization.

**No Apple Watch integration code has been added.** This report adds documented requirements and evidence, not native functionality. There is no Xcode/watchOS project in the audited repository. The prior audit did not cover every relevant detail; this matrix expands it.

Sources are official Apple documentation retrieved during this session. `apple-sources/index.json` records 27 directly fetched API/release-note pages with URL, title, date, byte count and SHA-256. Additional support/news/HIG sources were read through web search. Publication date, API availability and retrieval date are distinct. Existing APIs remain relevant in 2026; not every item was introduced in 2026. This is a scoped requirements inventory, not a claim to enumerate every Apple document or to have passed Apple certification.

The 2026 additions explicitly checked include limited-history HealthKit access, watchOS 27 lifecycle deprecations, optional workout zones/complication behavior, and the SDK/ARM64 submission requirements. Unrelated reproductive-health, clinical-record, dive/depth and AI features are not automatically enabled merely because they appear in the same release notes.

## Proposed product sequence

Pair using Apple’s system setup → install/sign into the companion → authorize relevant health types → select a routine and acknowledge its version → explicit Start → Watch acknowledges recording → mirrored metrics and explicit commands → Watch-owned completion/save → persisted sync acknowledgement → one account history record.

A disconnected Watch must retain the selected plan and pending events. A delayed completion must target the original stable set, never the next unfinished set. Starting, pausing a workout, pausing rest, and selecting a routine are distinct actions. The current web app’s timestamp-based rest timer and server retry deduplication are useful foundations; they do not supply native HealthKit/WatchConnectivity behavior.

Check availability per symbol and per platform. Mirroring starts at iOS 17/watchOS 10, but the directly checked [recoverActiveWorkoutSession](https://developer.apple.com/documentation/healthkit/hkhealthstore/recoveractiveworkoutsession(completion:)) and [typesToCollect](https://developer.apple.com/documentation/healthkit/hkliveworkoutdatasource/typestocollect) declarations list iOS 26/watchOS 5. Do not use the mirroring minimum as a blanket availability guarantee for phone-side recovery or collection APIs. In the proposed architecture, Watch owns recording and recovery; iPhone receives the mirrored session.

## Not established by this audit

Actual phone model/OS versions, developer-team signing, physical pairing, native build success, sensor accuracy, battery usage, device-specific availability, App Store approval, or real Watch communication. No production data was uploaded or altered.
