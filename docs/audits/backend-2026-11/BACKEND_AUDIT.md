# Backend audit, November 2026

Audit date: 9 November 2026 (Australia/Sydney). Baseline commit:
`53c48772beb19b08bc957400ebd24e329042d933`. Scope covered:

- the Fastify API (`server/`);
- the Cloudflare Worker gateway (`worker/`, `wrangler.jsonc`);
- operations tooling (`ops/`, CI workflows);
- the shared modules the API imports from `src/`;
- the backend tests.

Nothing was deployed, and no production or staging system was contacted.

## Method

1. **Baseline.** Server 76/76 on PostgreSQL 18.4, Worker 35/35, operations
   8 Python + 8 Node, and `build:server` all passed before any change.
2. **Parallel audits.** Six read-only audit agents ran in parallel, each over
   its own set of files: API core and quality; authentication and abuse;
   PostgreSQL and workspace integrity; coach tokens; Worker gateway;
   operations and CI. Each reported findings with file and line evidence, a
   severity and a confidence level. The agents were Claude Haiku-class
   subagents (`model: haiku` in the session runtime).
3. **Lead verification.** The lead checked every high-severity claim against
   the code and, for client-facing changes, against the web and iOS client
   code before accepting it.
4. **Implementation.** Four implementation agents each owned their own files
   (Worker, operations, coach tokens, authentication library). The lead
   implemented the API core, configuration, workspace and migration changes,
   reviewed every agent diff, and rewrote parts of them:
   - an implicit `AsyncLocalStorage` token context became an explicit write
     guard;
   - interpolated prune SQL became fixed statements;
   - the restore check now runs where `pg_restore` runs.
5. **Regression tests.** Every fix with an observable effect has a test on
   real PostgreSQL, or on the Worker or operations harness, that fails on the
   baseline.
6. **Independent review.** Two fresh reviewers (security, and data and
   compatibility) reviewed the final diff. Their verified findings were fixed
   or recorded as deferred below.

Severity scale:

- **P0:** data loss, authentication bypass, cross-member access or secret
  exposure.
- **P1:** a major reliability or security weakness.
- **P2:** a significant defect, gap or performance problem.
- **P3:** minor.

**No P0 issue and no authentication bypass or cross-member access path was
found.** The deny-by-default origin, member binding, Worker header and cookie
allowlists, digest-only coach tokens and the revision-checked write path all
held under review.
