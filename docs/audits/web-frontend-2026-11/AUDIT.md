# Web frontend audit, November 2026

Audit date: 9 November 2026 (Australia/Sydney). Baseline commit:
`53c48772beb19b08bc957400ebd24e329042d933`. Scope: the web application only
(`src/`, `index.html`, Vite configuration and the browser test suites). The
native app under `ios/`, the API under `server/` and the Worker were not
changed.

This pass follows the 26 October runtime audit
(`docs/audits/forma-runtime-quality-2026-10/`). It looked for defects that
remained after that work, then fixed the verified ones.

## Method

1. Baseline: clean install, then lint, format, types, docs, 151 unit tests and a
   guest production build all passed before any change.
2. Seven read-only audit agents, each with its own set of files: architecture
   and state; workout data integrity; routines and library; account and frontend
   security; main stylesheet; motion, media and secondary stylesheets;
   accessibility.
3. A live sweep of every page at 320, 360, 375, 390, 430, 768, 1024, 1280, 1440
   and 1920 px. It checked page overflow, elements outside the viewport,
   clipped text, touch targets and console errors, and ran axe (WCAG 2.0 to 2.2
   A/AA tags) at 390 and 1440 px. Targeted render checks covered the routine
   editor and the active workout at 320 to 1440 px.
4. The lead re-checked every high-severity claim against the code or the running
   app before fixing it. Four claims did not hold up ("Not reproduced" below).
5. Fixes were written either by the lead or by two implementation agents with
   separate files, then reviewed by the lead. Each important fix has a
   regression test that fails on the baseline and passes after.
6. Three new read-only reviewers checked the final diff for correctness,
   accessibility and security.

Severity: **P0** security, data loss or broken app; **P1** major functional,
accessibility or responsive defect; **P2** significant usability, performance or
visual problem; **P3** minor.
