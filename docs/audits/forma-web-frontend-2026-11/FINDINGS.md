The account follow-up is an explicit intent boundary: ordinary acknowledgement or refresh preserves a dirty draft; a consented conflict reload discards the training values the member reviewed, while retaining edits made after that reload began. The two gated reload rounds verify later name or goal input and email preservation. An old draft surviving every incoming update would not satisfy that behavior.

A hold's immediate timer-end cue remains a **duration alarm**, not a save acknowledgement. An owner already invalid in the displayed state cannot produce a completion cue; the latest-store updater separately rechecks identity and set validity. A replacement discovered only during a queued commit, or a failed commit, can occur after the physical-duration alarm has sounded. Saved-set notification still requires a successful result and a logged set. No universal no-cue-after-failure claim is made.
