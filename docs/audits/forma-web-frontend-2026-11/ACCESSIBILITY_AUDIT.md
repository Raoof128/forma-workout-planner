# Accessibility audit

The audit combines source review, axe checks, actual browser focus journeys and measured/visual rendering. These establish the checks described below, not a blanket WCAG certificate. Manual screen-reader sessions and physical Safari keyboard/zoom behavior remain unverified.

Same-route cloud recovery can replace the initially prepared error heading after the one-shot navigation observer disconnects. The explicit Skip action now prepares the current `main h1` with `tabIndex=-1` before focusing it. This preserves normal Skip scrolling and moves focus only after the member activates the link. Root reproduced the recovery failure in all three engines, then the same three cases passed in 13.5 seconds. The existing failed-GET regression retains its fresh-GET, no-PUT, no-page-error and unchanged `#account` assertions; it now also activates Skip and verifies the replacement Account heading receives focus. This functional follow-up changes no visual component and does not imply a manual assistive-technology pass.

The five initial design cases passed across all five development profiles. Two subsequent regressions each passed five focused profiles: narrow Security radio/control reachability and all tablet auth modes without internal clipping. Final visual account evidence covers 48 original/final pairs; the extended responsive sweep passed 88/88 states with zero page errors. An earlier development attempt was 189/190; an unchanged desktop WebKit security journey again timed out in a fresh-server rerun (37/38). No failed isolation assertion was observed, but assertions after the timeout were not completed. A trace-screenshot-only diagnostic subsequently completed the unchanged security journey within its original budget; full service-backed reruns and production outcomes remain owned by the test report. Exact evolving outcomes and receipts are maintained in [test results](TEST_RESULTS.md).

The macOS Tab investigation used bare controls and current primary Apple/WebKit/Playwright references. A calibrated volatile `NSArgumentDomain` override normalizes button/file keyboard tests only; it does not change global OS settings or prove physical Safari behavior. Anchor skipping exposed a real application drawer trap and was corrected within that existing open-drawer handler. See [source register](SOURCE_REGISTER.json), [responsive details](RESPONSIVE_AUDIT.md) and [motion](MOTION_REVIEW.md).

Primary explanatory guidance: [contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html), [drag alternatives](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html), [focus not obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html).
