## Reconciled reference drift

The 20 October master plan repeatedly uses a version-one envelope and a
1,661-entry catalogue. Current implementation takes precedence: native generated
resources derive from the version-two validator and runtime catalogue. Historical
IDs remain accepted with their original units. Selectable and accepted counts are
different concepts and must not be collapsed into one marketing figure.

Current programming fields include rep ranges, RPE, per-exercise rest, per-side
logging, cues, supersets, stable entry IDs and archived routines. The first native
slice must preserve those fields even where its editor does not expose every
advanced programming option. Legacy `plank` still logs ten-second reps; a timed
guide does not change a saved record's measurement profile.

The website's current policy is newer than the v1.2 policy named in the master
plan. Browser-specific guest-storage wording cannot be reused as a native privacy
statement. The bundled native privacy notice describes the actual local-only
slice separately and remains subject to pre-distribution legal review.

Older README, architecture and security prose includes staging/NO-GO wording.
Those historical paragraphs do not establish current deployment or native
readiness. No production health, deployed image version or account canary was
reverified here.

## Decisions for this milestone

1. Add an isolated native SwiftUI app with an iOS 17 deployment floor.
2. Keep the established F, warm canvas, graphite and lime identity.
3. Build an offline guest workout loop with transactional persistence first.
4. Derive catalogue, seed and parity fixtures from current JavaScript source.
5. Keep local-save state distinct from any future account-sync state.
6. Add no native sign-in or account-creation surface until a reviewed native
   authentication contract, identity partitioning and deletion flow exist.
7. Preserve the current web app, API, database and production publication state.
