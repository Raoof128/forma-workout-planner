# CLAUDE.md

Guidance for Claude Code sessions in this repository. It condenses `AGENT.md`
(constraints, checks, a long dated log), `CONTRIBUTING.md`, `SECURITY.md`, the CI
workflows and `docs/`. Those stay the source of truth: where this file and the
code disagree, trust the code and fix this file.

Read `AGENT.md` (Constraints, Checks, and the log entries for the area you touch)
and `CHANGELOG.md` before changing code, and append to both afterwards.

## What FORMA is

A workout planner: members plan routines, log sets (weight/reps, time, distance)
and review history and progress. Weights are kilograms; dates and weeks use
Australia/Sydney.

- **Web app** (`src/`): React 19 + Vite SPA, in **guest mode** (browser
  `localStorage`) or **account mode** (PostgreSQL).
- **Account API** (`server/`): Node + TypeScript, Fastify 5, Better Auth, `pg`. One
  validated JSONB workspace per member, with revisions and idempotent writes.
- **Worker** (`worker/index.ts`, `wrangler.jsonc`): serves the built SPA (`dist/`)
  and is the same-origin `/api` gateway.
- **Ops** (`ops/`): Docker Compose stack, backup/restore and monitoring for the API
  host, plus the edge-monitor and dashboard Workers.
- **Native app** (`ios/`): SwiftUI iPhone app, watchOS companion, WidgetKit
  extension and workout Live Activity. The Xcode project is generated by XcodeGen
  from `ios/project.yml`. Not an App Store release.

### Request flow (account mode)

```text
Browser -> Worker (static assets + /api gateway)
        -> Cloudflare Access (service token) -> Cloudflare Tunnel
        -> cloudflared container -> Fastify API (http://api:3000) -> PostgreSQL
```

- The browser talks only to its own origin; never to PostgreSQL or the API origin.
- Worker to API is authenticated by the Access service token (`ACCESS_CLIENT_ID`,
  `ACCESS_CLIENT_SECRET`) and the shared secret `FORMA_WORKER_SECRET` (equal to the
  API's `ORIGIN_SHARED_SECRET`). Neither identifies a member; the Better Auth
  session cookie does.
- The Worker forwards allowlisted headers and `forma.*` cookies only; bearer
  coach-token routes are the sole place `Authorization` is forwarded.
- Guest mode keeps working when the API or Tunnel is down.

| Environment | App                              | Protected API origin                 |
| ----------- | -------------------------------- | ------------------------------------ |
| Production  | `forma.raoufabedini.dev`         | `forma-api.raoufabedini.dev`         |
| Staging     | `forma-staging.raoufabedini.dev` | `forma-api-staging.raoufabedini.dev` |
| Dashboard   | `forma-ops.raoufabedini.dev`     | owner-only, behind Cloudflare Access |

Staging and production are fully separate (Worker, Tunnel, Access policy, service
token, database, roles, secrets, backup bucket). `workers.dev` and preview URLs are
disabled.

### Guest versus account builds

`VITE_ACCOUNT_MODE` is read at build time (`src/account/AccountProvider.jsx`,
`src/components/Account.jsx`). Only the exact value `guest` selects guest mode;
unset or anything else is **account mode**, which needs the API or the isolated test
harness. Playwright's dev and production smoke suites run guest; the account suites
and the Worker deploy scripts build `account`. `VITE_*` values land in the public
bundle: never put a credential in one.

## Dev setup

Node `>=22.12.0` (`engines`); docs and CI use **Node 24**; the API image pins Node 26.
npm only; `tsx` runs server code and tests.

```sh
npm ci                                # reproducible install from the lockfile
npm run dev                           # Vite on 0.0.0.0:5173 (account mode)
VITE_ACCOUNT_MODE=guest npm run dev   # guest mode, no backend
npm run preview                       # serve dist/ (4173)
npx playwright install chromium firefox webkit   # before any browser suite
npm run server:dev                    # tsx watch server/index.ts
npm run server:migrate                # needs the migration-role DATABASE_URL
npm run worker:dev                    # wrangler dev (backend 127.0.0.1:3000)
npm run build:server                  # tsc to build/server and copy migrations
```

Account UI against a local API (Vite proxy; these two variables are not `VITE_`
prefixed and never enter the bundle):

```sh
FORMA_API_TARGET=http://127.0.0.1:3000 \
FORMA_DEV_WORKER_SECRET='local-only-value-at-least-32-characters' \
VITE_ACCOUNT_MODE=account npm run dev
```

The API needs `APP_ORIGIN`, `AUTH_SECRET`, `ORIGIN_SHARED_SECRET` and
`DATABASE_URL`. `.env.example` lists the production-host set; copy it outside the repo.

### Bar before claiming work complete

1. Any code change:
   `npm run lint && npm run format:check && npm run typecheck && npm run docs:check`
   (the Checks block in `AGENT.md`), plus `npm run build` for web changes.
2. The layers covering what you touched: `test:unit`; `test:server` for `server/` or
   `src/storage.js`; `test:worker`; `test:operations` for `ops/`; the relevant
   Playwright specs for UI; `test:accounts` for account flows. Broad changes: also
   `npm test && npm run test:browser:production`.
3. A regression test that fails before the fix; data-integrity changes need
   real-PostgreSQL coverage.
4. **Report exactly what ran and what did not** (for example Docker off, so
   `test:server` and `test:accounts` did not run). Never describe an unrun check,
   staging, email or backup step as passing. A red, pending or cancelled CI run is
   not a pass; never merge on one.

Recorded environment behaviour: host load causes 30 s timeouts (rerun serially; the
`routine-drag` / `routine-library` specs are load-flaky, so rerun a failed job once
before investigating). Firefox may not launch in an agent sandbox, and some WebKit
keyboard-focus cases failed identically on unmodified `main`: compare to a baseline
first. Some dev specs hard-code `127.0.0.1:5173`; if another session holds it, run a
scratch copy of `tests/` on a private port. Assert image loads with a retrying
`toHaveJSProperty("naturalWidth", n)`. Only the page toast may use `role="status"`.

## Code conventions

- **Languages:** JS/JSX for the SPA and shared `src/*.js`; strict TypeScript (NodeNext)
  for `server/`, `worker/`, account test scripts. Dependencies are pinned to exact
  versions (`npm install` writes `^`; strip it).
- **Formatting:** Prettier 3 defaults, no config file (`npm run format`). ESLint flat
  config (`react-hooks/exhaustive-deps` and `no-unused-vars` are errors); it stays on
  9.39.5 because the plugins lack ESLint 10 support (upgrading breaks `npm ci`).
- **UI and persistence:** reuse existing components (`UI.jsx`, `ActionsMenu.jsx` for
  per-item menus); keep focus order, dialog semantics, reduced motion and 320 px
  usability; local assets only. Guest writes stay in the guest store boundary, cloud
  writes in the authenticated workspace repository; no effects saving stale snapshots;
  validate imported data and preserve originals when recovery is needed.
- **Workspace schema:** `src/storage.js` is shared with the API. Do not change the
  backup version or accepted fields without documenting compatibility and recovery
  (`docs/data-model.md`). Keep aggregate bounds checked before zod parsing. A new
  `src/` import from a server module must be added to the explicit copy list in
  `ops/Dockerfile` (and `ops/Dockerfile.dockerignore`).
- **Catalogue contract:** `exercises` / `exerciseById` keep every historical ID and
  metric; `selectableExercises` is the reviewed picker view. Never mutate saved IDs
  or reinterpret units. Build session entries with `sessionEntry` / `addedEntry`
  (`src/workoutSession.js`), never by hand.
- **Generated files, never hand-edit:** `src/catalog/demos.json`,
  `src/catalog/animations.json`, `public/exercise-animations/`, `assets/exercise-svg/`,
  `ios/FORMA/Resources`, `ios/Fixtures`. Rebuild with the owning script and confirm
  byte-identical output:

  ```sh
  npm run catalog:sync               # scripts/import-exercises.mjs
  npm run catalog:curate             # scripts/build-catalog-curation.mjs
  node scripts/build-exercise-media.mjs   # then check-exercise-media.mjs, audit-exercise-equipment.mjs
  python3 scripts/exercise-svg/build.py
  node scripts/build-ios-resources.mjs   # add --check to fail on drift
  ```

  Do not run Prettier over `docs/research/original-art/registry.json` (reflows ~9,000
  lines) or `docs/research/exercise-logging-review.json`; both have fixed formatting.

- **Legal text** lives only in `src/legal/content.js`; bump its version and effective
  date for material changes. New data collection, providers or analytics need a
  Privacy Policy update first (`docs/legal/README.md`).
- **Docs:** link repo files through `blob/main/`, never a feature branch. Run
  `npm run docs:check` after any Markdown change; it also rejects an npm command in
  a code span or fence that names a script missing from `package.json`.

### Commits, branches and PRs

- Never commit to `main` directly; use a focused branch (`feat/…`, `fix/…`,
  `maintenance/…`; Dependabot uses `dependabot/…`).
- Conventional Commits with a lowercase imperative subject and optional scope, for
  example `fix(ops): judge the tunnel by cloudflared readiness, not log lines`.
  Types in use: `feat`, `fix`, `docs`, `test`, `ci`, `build(deps)`, `perf`, `chore`.
  The body explains why. PRs merge as `Merge pull request #N from Raoof128/<branch>`.
- PR text: problem, behaviour, validation, known limits. If `gh` cannot connect, open
  the PR via the GitHub REST API with `curl` and `$(gh auth token)`. Claude commits
  carry the session's `Co-Authored-By` trailer.

## Change protocol (mandatory)

Every change adds a dated entry to **both** `AGENT.md` (directly under `## Log`) and
`CHANGELOG.md` (directly under `## Unreleased`), newest first:

```markdown
### Raouf: YYYY-MM-DD — short title

- **Scope:** what was asked or investigated.
- **Summary:** what changed and why.
- **Files:** paths touched, including `CHANGELOG.md` and `AGENT.md`.
- **Verification:** commands actually run and their real results; what was not run.
- **Follow-ups:** open items, deploy state, owner decisions.
```

- Dates are **Australia/Sydney**, not UTC.
- Put durable rules and gotchas in the entry (the log is how knowledge persists) and
  say when a new rule supersedes an older one.
- State "not deployed" when that is the case; never claim unobserved results.
- Avoid prose or image tags that look like credentials: gitleaks false positives on log
  text have happened several times. The fix is an exact-fingerprint line in
  `.gitleaksignore`, never a path or rule allowlist.

## Security constraints and never-do rules

The repository is **public**: never commit secrets, IP addresses, tokens, real member
data, workout backups or exploit recipes. Use synthetic data everywhere.

- Security boundaries live on the server and in the Worker, never only in the UI.
  Member identity comes from the server-validated session; never accept an owner,
  user ID or role from a URL, body or header.
- `server/app.ts` is deny-by-default: only exact `/healthz` is public, every other
  path needs the Worker secret, mutations need the exact app `Origin`, auth requests
  must be JSON objects. New routes stay inside this model.
- Better Auth endpoints are reachable only through `AUTH_ROUTES`; a new client call
  means adding it there with a test. Redirects and emitted `Location` stay same-origin
  (`isSafeRedirect`).
- Password attempts go through `reserveAttempt` and settle with `settleFailure`,
  `refundAttempt` or `clearSignInFailures` (`server/throttle.ts`). Do not widen the
  Worker's header or cookie allowlists without a test. Do not call `sign-in/email` in
  the browser while signed in (it clears the session cookie before the code step).
- Coach tokens (bearer, `read` or `full` scope): digest-only storage, never logged or
  returned after creation, never valid on `/api/account/*` or `/api/auth/*`, never
  widened in place. Edits go through `patchWorkspace` -> `writeWorkspace`, the same
  locked, revision-checked path as `PUT /api/workspace`; add no second write path.
- New tables need a numbered migration **and** an entry in `ops/grant-runtime-access.sql`
  (plus the role/grant scripts). Never edit an applied migration (checksums are
  enforced). Migrations are forward-only and must stay backward compatible for the
  rollback window.
- Logs carry fixed event names, correlation IDs and HMAC client keys. Never log
  passwords, cookies, tokens, TOTP codes, auth links, raw identities, request bodies
  or workout payloads.
- Worker secrets (`ACCESS_CLIENT_ID`, `ACCESS_CLIENT_SECRET`, `FORMA_WORKER_SECRET`) are
  set per environment with `wrangler secret put … --env <env>`. Never in
  `wrangler.jsonc`, Vite variables, the bundle or Git. API secrets live in a root-only
  env file on the host; keep `MIGRATION_DATABASE_URL` out of the API container.
- Local deploy credentials live in the owner's env file outside the repo (`AGENT.md`
  names `~/.config/forma/production-deploy.env`; ask the owner). Source it inside the
  command; never print values; do not use the SSH password in it (SSH is key-only).
  Use one-hour scoped tokens.
- **`AUTH_SECRET` warning.** It signs cookies, derives member references and throttle
  keys, and encrypts TOTP secrets and recovery codes. Rotating it ends every session,
  changes every member reference and makes existing 2FA secrets undecryptable. Rotate
  only if believed exposed, with a 2FA re-enrolment plan. Backups do not contain it:
  preserve it separately.
- `.gitleaksignore` holds exact historical fingerprints only; CI Semgrep
  (`p/nodejsscan`) blocks `createHash("sha1")` in `scripts/`. Do not weaken either.
- No destructive or irreversible action (account reset, restore over a live DB, data
  deletion) without explicit owner instruction. Restores go only into a separate
  `forma_restore_*` database. Never export member rows to the sandbox. Account browser
  tests use disposable schemas and an in-memory email sink; never aim them at live data.

Runbooks, thresholds and the sign-in-lock procedure: `docs/security/incident-response.md`.
Reporting policy: `SECURITY.md`.

## Deploy and release

**Staging before production, always.** When the API image changes (catalogue/IDs,
`src/storage.js`, server, auth, Node base bumps), release the API before the matching
frontend, in each environment: an older API rejects new IDs.

**Explicit owner approval is required, per action, for:** any production deploy
(Worker or API: agent sessions in auto mode are refused these; do not work around it,
hand the owner the exact command); any Droplet, Compose, database, Cloudflare, Access,
DNS or email-provider change; `git push`, creating or merging PRs, deleting branches;
sending mail or messages or anything outward-facing; App Store/TestFlight; rotating
secrets; restores, resets or any touch of member data. Local reversible work (edits,
tests, builds, a feature-branch commit when asked) needs no extra approval.

### Worker

```sh
npm run worker:deploy:staging       # account-mode build, then scripts/deploy-public.mjs --staging
npm run worker:deploy:production    # same, production (owner approval)
npm run worker:deploy:dashboard     # ops dashboard; no staging env; behind Access
```

- `scripts/deploy-public.mjs` uses a management token from the environment
  (`CLOUDFLARE_API_TOKEN`) to mint a one-hour scoped token and revokes it on every
  exit path. Keep the token in a mode-0600 file outside the repo.
- Verify staging (site loads, `/api/health` 200, anonymous `/api/workspace` 401, live
  asset hashes) before production. Keep the previous Worker version for rollback.
- Mac gotchas: Node's fetch can stall over IPv6, so set
  `NODE_OPTIONS=--dns-result-order=ipv4first`; Wrangler may need `CLOUDFLARE_ACCOUNT_ID`
  when a login sees two accounts; a failed custom-domain update after "Uploaded" can
  still leave the new version live, so confirm with `wrangler deployments list`.
- The edge-monitor Worker (`ops/wrangler.monitor.jsonc`, every 5 minutes) has no npm
  script; its deploy procedure is not documented in the repo.

### Droplet (shared host, about 2 GB RAM, no swap)

```text
/opt/forma-staging/      .env  ops/  releases/<name>/  operations/
/opt/forma-production/   .env  ops/  releases/<name>/  operations/
```

- Per environment (`ops/compose.yaml`): `db` (PostgreSQL 18), `api`, `migrate`
  (profile `migrate`, one-shot), `cloudflared`. No published ports; the database
  network is internal; containers are read-only, non-root and resource-limited.
- Staging layers `compose.small-host.yaml`, production `compose.production-host.yaml`
  (256 MiB API and DB, 96 MiB connector). On-host copies intentionally differ from the
  repo. Check host capacity before raising limits; never touch unrelated containers.
- **Always pass `-p forma-<env>`** with `--env-file` and explicit `-f` files.
  `compose.yaml` starts with `name: forma-staging`, so a command without `-p` acts on
  **staging** (this once recreated staging's database from production's files).

  ```sh
  docker compose -p forma-production --env-file ../.env \
    -f compose.yaml -f compose.production-host.yaml ps
  ```

- Release folders are root-only: work in one `sudo` shell (SSH is key-only as the admin
  user). In a script piped to `sudo bash -s`, give every `docker compose run/exec`
  `< /dev/null` or it swallows the rest of the script.
- The DB admin role is `$POSTGRES_USER` in the `db` container (not `postgres`); the
  migration ledger is `forma_schema_migrations`; the Tunnel token file must be owned by
  UID/GID 65532, mode 0400, or Cloudflare returns 1033.

### API release recipe (per environment, staging first)

1. Build the image off-host for `linux/amd64` (the host is too small), save and gzip
   it, transfer, verify the SHA-256, `docker load`. Use a unique tag; keep the previous
   image.
2. **Verified encrypted, signed off-host backup first:**
   `cd /opt/forma-<env> && python3 operations/account-operations.py operations/config.json backup`
3. Migrate:
   `IMAGE_TAG=<tag> docker compose -p forma-<env> … --profile migrate run --rm migrate`.
   If tables changed, install the current `ops/grant-runtime-access.sql` and run
   `ops/grant-runtime-access.sh` before the API starts.
4. Set `IMAGE_TAG` in the host `.env`, `docker compose -p forma-<env> … up -d --no-deps api`,
   wait for health, switch back if unhealthy.
5. Second backup; compare row counts and unrelated-container IDs; scan API logs.
6. Deploy the matching Worker for that environment.

`docs/qa/holds-timer/api-release.sh` implements steps 1-5 but hard-codes a
release-specific counts file: adapt it, do not run it blindly. Record evidence in
`docs/qa/<release>/`.

**Rollback:** only to a data-compatible image; schema is never rolled back
automatically. **Do not roll the API back once a member has saved a timed hold**: older
images reject those IDs and the workspace stops loading. Fix forward. (Schema was at
`0006` in the 2026-10-22 entries.)

### Backups and monitoring

- Daily age-encrypted, Ed25519-signed backups to a per-environment private off-host
  bucket, 34-day lifecycle (the Privacy Policy promises deletion within 35 days; do not
  lengthen retention without changing it). Restore only into a `forma_restore_*`
  database after verifying the signature.
- Host monitor: `ops/account-operations.py <config> monitor` on a one-minute timer per
  environment mails the owner on signals such as `tunnel_error`, `backup_failed` and
  lockout events. Its systemd units are `forma-staging-monitor.service` and
  `forma-production-monitor.service` (seen in the host syslog; the unit files are not in
  this repo). Each run logs `{"monitorSignals": [...], "healthy": ...}` to syslog, which
  the read-only Sentinel observer (host `portfolio-droplet`, root `logs`) can read;
  container logs under `/var/lib/docker` are outside its roots. The tunnel check
  asks cloudflared's `/ready` over the internal `tunnel` network and alerts after two
  consecutive failures. Changing the script means installing it on the host and
  recreating `cloudflared` (Compose pins its metrics server to `0.0.0.0:20241`); confirm
  `/ready` answers on both hosts first.
- Independent: the `forma-operations-monitor` Worker checks public gateway health and
  backup freshness; the owner-only dashboard reads sanitized monitor state only.

## Known gotchas

- **Compose project name** (above) is the costliest mistake in the log.
- **Load display is UI-only.** Keep `src/exerciseLoad.js` and
  `src/catalog/logging-review.json` out of `src/exerciseMetrics.js` and
  `src/storage.js` (the API imports those, so edits force an API redeploy).
  `unit/exercise-load.test.js` fails while any selectable exercise is unreviewed.
- **Timed holds:** a timed identity is `forma-<saved ID>` with `metric: "duration"`,
  produced by `npm run catalog:curate` from reviewed `measurementCorrections` in
  `docs/research/exercise-quality-review.json`. Never put them in
  `programming-aliases.json`; never give a rep entry the hold timer. A new one also
  needs its `logging-review.json` entry, its original-art registry entry and (for
  one-side holds) its `unilateral.json` row; `unit/hold-metric-migration.test.js`
  pins this.
- **Unilateral catalogue:** `catalog:sync` does not touch `src/catalog/unilateral.json`;
  new imports need their rows reviewed. Per-side sets store `sides: { left, right }`
  and keep `reps` as the total; never store per-side reps in `reps`.
- Time and distance never count as kilogram volume or 1RM; keep the 100-exercise
  session/routine and aggregate workspace bounds. Server tests register members by
  display name, unique per file.
- **Drag surfaces:** prescription rows never scale (tests assert exact positions); a
  lift box must not extend past its row (trips the 540 px overflow test); tests wait
  for the previous drop to settle. Reuse the `--spring-*` / `--ease-standard` tokens.
  Carousel prev/next use `aria-disabled`, so tests press Enter instead of `click()`.
- **Self-hosted media only.** CSP is `default-src 'self'`, `object-src 'none'`,
  `frame-ancestors 'none'`: animations load via `<img>`, clips never autoplay, no
  hotlinked provider URLs. HTML responses carry `no-transform` to stop Cloudflare
  injecting a beacon the CSP blocks.
- **Dependencies:** keep exact pins and the narrow Miniflare -> Undici `overrides`
  entry; after changing either, revalidate clean `npm ci`, tooling and the API image.
